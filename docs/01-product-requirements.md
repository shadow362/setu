# Product Requirements Document (PRD)

## Overview

Setu is an open-source personal cross-device inbox designed to help users intentionally move information between their own devices.

The initial version focuses on sharing text and links between an Android phone and a Windows desktop, allowing users to continue their work regardless of whether both devices are online at the same time.

---

## Problem Statement

People frequently discover useful information on one device while working on another.

Current methods of transferring this information—such as messaging themselves, relying on browser history, emailing links, or using note-taking applications—often interrupt their workflow and create unnecessary friction.

Setu aims to provide a simple, dedicated solution for intentionally moving information between personal devices.

---

## Product Goal

Build the simplest reliable system for transferring text and links between a user's Android phone and Windows PC.

The experience should require minimal effort while remaining reliable, fast, and easy to understand.

---

## Target Users

### Primary Users

* Developers
* Students
* Researchers
* Professionals who regularly switch between a phone and a desktop

### Initial User

The first user is the project creator, ensuring that the product is built around solving a real and personally experienced problem.

---

## MVP Scope

The first version of Setu will support:

* User authentication
* Sending text
* Sending links
* Android Share Sheet integration
* Desktop inbox
* Offline delivery
* Mark items as read

---

## Out of Scope

The following features are intentionally excluded from the first release:

* Images
* File sharing
* Clipboard synchronization
* Browser extensions
* AI features
* Team collaboration
* Notes and document editing
* Tags and folders
* Search

---

## Success Criteria

The MVP will be considered successful if a user can:

* Send a link from Android and access it later on Windows.
* Send text from Windows and access it later on Android.
* Continue using the application even when one device was offline during the transfer.
* Complete these actions with minimal friction.
